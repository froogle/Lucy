# Bar panel

- **Shape:** `omarchy-plugin/` is an Omarchy (Quickshell) bar-widget plugin. Its QML holds no product knowledge: it reads `lucy status --follow --json` (`lucy::panel`), writes through `lucy set`/`lucy unset` (a choice's `key`), and runs `lucy service` and `lucy end`, never `systemctl`.
- **Input dialog:** the panel holds the `input` role through `lucy input --json` (`lucy::input::hold`), which keeps running, reclaims the role whenever lucyd comes back, prints lucyd's `input.open`/`input.close` lines as they came and sends each `{"method": "input.answer"|"input.cancel", "params": ..}` line written to its stdin. It passes field kinds through unread, so a new kind needs only a box in `Panel.qml`'s `InputBox`. A question opens the panel on the dialog, with the keys in its first typed box (the dialog is the `KeyboardPanel`'s `focusTarget` while it's up, since the panel gives that the keys as it opens); Send empties every box before the answer goes, and a secret is never put on a command line. Option labels come from `i18n/en.json` where it has an `option.<value>` string (Superwhisper), else the value itself. A new choice goes in `panel::Snapshot` with its key, plus a row in `Panel.qml` that binds it by its snapshot name; `Service.qml` reads every choice the snapshot holds.
- **Details window:** an `input.open` with `items` shows them in the `InputBox` above its boxes, or alone when it has no `fields`, each a `Text.MarkdownText` in a scrolling `Flickable` with a rule between items. `readable` first turns raw HTML (escaped `<`), images (alt text) and links (text plus `[url]`) outside code into text, since Qt's Markdown would draw the HTML, fetch the images and make links look clickable. Alone, Esc or Close only drops it in the panel (`Service.dismiss`): nothing goes to lucyd, which keeps the role held.
- **Lifetime:** `lucy status --follow` asks Linux for SIGTERM when its parent dies (`PR_SET_PDEATHSIG`), since the bar gives it no stdin; `lucy input --json` ends when its stdin closes, which happens when the bar dies.
- **States:** lucyd's socket says waiting or session; while it's away, `systemd::activity` (`systemctl show`) says stopped, starting or failed. lucyd is `Type=exec`, so systemd calls it active before it listens: active without a socket is starting for `panel::STARTUP` (a minute), then failed.
- **Install:** each yes to starting at login in the Service section links the plugin to `$XDG_CONFIG_HOME/omarchy/plugins/lucy-panel` (`Env.omarchy`) when that dir exists, replacing an older link (`panel::link`). It is found through `Env.bin`: `omarchy-plugin/` beside `lucy`, else in `../share/lucy/` (where `scripts/install.sh` puts it), else in the checkout whose `target/<profile>/` holds `lucy` (with the shared `target/`, the main checkout). If none has it, the section says so and the enable stands. The user adds it to the bar. Lucy never edits `shell.json`.
- **Checks:** `omarchy-plugin/tests/run.sh` runs `Panel.qml` offscreen in Quickshell against a fake `lucy`, `systemctl` and `omarchy-launch-tui`, then checks the commands it ran, that none was `systemctl`, and the replies the Input dialog wrote to the fake `lucy input --json`. The harness feeds `input.open` and `input.close` straight to `Service.inputEvent`, and presses keys with QtTest's `TestEvent`, which is why the panel sits in a window there; `omarchy plugin validate omarchy-plugin` checks the manifest. Neither is in `scripts/check.sh`, since CI has no Quickshell: run both after changing the plugin. With `LUCY_PANEL_CAPTURE=<path>.png`, `run.sh` also saves the Details window above the Input dialog there, to check by eye.

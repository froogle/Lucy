# Setup and the `lucy` pages

- **Shape:** `lucy` (no arguments), `lucy setup` and `lucy credentials <plugin>` are one full screen (ratatui on crossterm), `menu::run`, opened at `menu::Open`; they refuse a stdin or stdout that isn't a terminal. It is a list of sections (`sections::Section`), each a page: `ui::Rows` lists its rows and the letters that act on them, and a row's questions run one at a time on `ui::Ui`. A section that needs lucyd still opens while it is stopped, says so and offers to start it. Approvals are granted only by voice, so their section only revokes. Esc anywhere is `Stop::Back`: on a row's question it goes back to the page, on a page to the list. The walk (no `config.toml`, or `lucy setup`) opens each section with a last "Next" row; after a row is picked the cursor moves to the next one, so Enter alone walks every suggestion. Sections read their paths and `PATH` from `lucy::Env`, never the process environment. Ctrl-C arrives as a key in raw mode; ratatui's panic hook restores the terminal. An installer runs outside the full screen (`Keys::outside`), since it may ask for a password.
- **Settings:** `lucy::settings` is the one writer of `config.toml` (`settings::write` of `Change::Set`/`Unset`, through `lucy_config::set`/`unset`, comments kept): `settings::Key` is each setting `lucy` changes, and `Key::applies` says whether lucyd takes it up at the next Session or only after a restart (Whisper's model, which stays loaded). Installing Piper or Kokoro needs no restart: while a TTS Provider can't be found, lucyd looks for it again at each Session (setup still offers a restart after installing Piper). A new setting gets a `Key` and its `Applies`, read from where lucyd loads it. `lucy set`/`unset` also take `stt` (`settings::SPEECH`), the panel's Speech-to-text row: `superwhisper` or one of Whisper's models, written as `stt.kind` and `whisper.model` together.
- **Tests:** `crates/lucy/tests/support/mod.rs` gives each test its own XDG dirs, an in-process lucyd with inert adapters, and a `PATH` holding only the fakes a test writes (`Home::fake`, logged to `<name>.log`), so a fake's body uses shell builtins or absolute paths (`/bin/mkdir`). `Home::with_mic(level)` gives its lucyd a microphone that stays at that RMS level, for the meter. `Home::tui` runs `lucy` in-process on ratatui's `TestBackend`, pressed by a `ui::Script`, with a `FakeStore` keyring (`Home::tui_with` takes an `Env` and store); a script that runs out, or has keys left over, fails the test. `Script::then` runs something while a question waits, and `idle` presses nothing more, for a question `Ui::close_on` watches (`lucy input` watches for `input.close`). `Tui::shown` is every piece of text shown, rows and options included; `Tui::screen` is the last screen. `Home::spawn_lucyd` starts lucyd mid-test, as a fake `systemctl start` would. Plain commands still run the real binary.
- **Tests inside lucyd:** `test.mic_level` and `test.wake_word` run in the Session runner (`runner/setup.rs`), refused while a Session is open. Under `Harness::hearing`, the fake wake word's score is each frame's first sample.
- **systemd:** the units are `dist/systemd/*.service`. When systemd doesn't know `lucyd.service`, the Service section and starting lucyd write them to `$XDG_CONFIG_HOME/systemd/user/` running the binaries beside `lucy`. `systemd::run` (the Service section's letters, and `lucy service start|stop|restart`) clears a crashed lucyd's start limit before a start or restart. The Service section's row asks whether Lucy starts at login, so a yes enables again even when lucyd already is. Tests use a fake `systemctl`; never enable the units in your own session.

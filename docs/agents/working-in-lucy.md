# Working in Lucy

Facts about the codebase that aren't obvious from reading it.

## Checks

`scripts/check.sh` runs every gate: fmt, clippy, tests, the client-deps check, the glossary-term check, the lint-allow check, the test-sleep check, the comment check and `cargo deny`. The pre-commit hook runs it once you've run `git config core.hooksPath .githooks`; a commit that only touches markdown, `docs/` or `.scratch/` runs just the glossary check. Commit with the hook on; `--no-verify` leaves the gates to CI.

`target/` only grows (108 GB by slice 6). When a ticket is done and merged, with no agents running, run `scripts/clean.sh`: it clears the shared `target/` and the prototypes' own `target/` folders, prunes stale worktrees and says how much it freed. It refuses while another worktree exists. The next build is cold. Run it after removing a worktree too: its test binaries stay in the shared `target/` and still look for fixtures and the schema under the removed worktree's path.

## lucyd test harness

- **Where it is:** `crates/lucyd/tests/harness/mod.rs` starts lucyd in-process through `lucyd::spawn(Options { .. })` and connects through the real `lucy-ipc` client.
- **Fakes:** they plug in through `Options.adapters`.
- **Config:** `Harness::with_config(toml)` writes the `config.toml` lucyd reads at each Session start; `Harness::start()` has none, so defaults apply.
- **Clock:** lucyd's timers (the silence timeout, the 8 s end of a false wake, the wait for an answer, Authoring budgets) count on `Adapters.clock`. The harness's `clock` stands still until `advance`, which returns once every timer that went off has been handled. After an input the test can't see lucyd handle, `advance_once_set` or `advance_once_stopped` waits for the timer first; `Harness::barrier` makes earlier commands, Thinking and TTS events take effect first. A transcript is handled unseen, so `Harness::mumble_handled` waits until lucyd has handled an empty one. Timer tests never sleep. The wait for an answer doesn't run while a reply is being transcribed, so the reply is always heard first.
- **Real binaries:** the harness runs the `lucy` binary cargo builds next to the test binary. `cargo test -p lucyd` on its own needs `cargo build -p lucy` first; `cargo test --workspace` handles this.
- **Fixture Plugin:** `crates/lucyd/examples/fixture-plugin.rs`, a tiny MCP stdio server. `Harness::install_plugin` copies it into a Plugin folder and `Harness::approve` pre-seeds `approvals.toml`. `cargo test -p lucyd` builds it, but `--test <name>` alone doesn't: run `cargo build -p lucyd --examples` first.
- **News Plugin in lucyd:** `tests/news.rs` installs the real `lucy-news` binary as a shipped Plugin; `cargo test -p lucyd` on its own needs `cargo build -p lucy-news` first.
- **Helpers:** `Harness::start` is a returning user (a `persona.md`, no config) and `first_run` one with no `persona.md`; `with_thinking` and `with_superwhisper` swap a real adapter in for the fake. `scratch()` is a dir outside every Plugin folder and Lucy's state. `install_plugin` and `install_shipped_plugin` write the Manifest beside the fixture Plugin as `./fixture-plugin`; `approve` pins the Plugin as it is now (the user copy if there is one) and saves each Manifest tool's input schema as `{"type": "object", "description": "approved <tool>", ..}`. `raw_exchange` sends one raw line, to check the wire format without the client in the way. The fakes record what lucyd did: `FakeStt` (`script`, `script_failure`, `hold`, `take`); `FakeThinking`, which streams deltas, a `SentenceEnd` after each sentence and `TurnEnd`, as the real `claude` adapter streams a recorded transcript; `FakeTts`, where each sentence plays until `finish_playing` and `fail` fails every later one with `FAKE_TTS_FAILURE`; `FakeNotifier`, whose `shown` and `next_notification` return only notifications the test hasn't read; `FakeLauncher`; and `FakeEchoCanceller`, which passes the mic through until `cancel_everything`. `FakeMic::feed` waits while the ring is full, and every device is there until `unplug`. `assert_no_level_on_bus` goes after `assert_nothing_private_on_bus`.
- **Drop order:** `Harness`'s fields drop in order: `daemon` first, so lucyd stops before its runtime dir goes away, then the model-text check over every notification it showed.

## Plugins

- **News Plugin:** `crates/lucy-news` is the shipped reference Plugin; `manifest.toml` beside it is the Manifest Lucy ships. Its Source catalogue (feeds and "AI summary allowed" flags) is `src/catalogue.rs`, taken from each Source's terms (`.scratch/lucy-v0-1/research/news-site-access.md`); re-check the flags against them and the Anthropic and OpenAI terms before each release, Sky News's first (its terms couldn't be found), and keep `[access] network` matching the readable feeds' hosts (a unit test checks). Sites the user names outside the catalogue (`src/discover.rs`) can't be listed there; the Manifest's comment says so.
- **Omarchy Plugin:** `crates/lucy-omarchy` is the shipped desktop Plugin and the pattern for other desktops; `manifest.toml` beside it is the Manifest Lucy ships. It dispatches to Hyprland over its request socket, and since Hyprland 0.56 a dispatcher is a Lua call (`dispatch hl.dsp.window.close({ window = "address:0x…" })`, answered `ok`); `/usr/share/hypr/stubs/hl.meta.lua` lists them. Layouts go through Omarchy's `omarchy-hyprland-workspace-layout-*` commands, which also remember the layout across logins and update the bar; the toggle cycles dwindle (tiling), scrolling and floating. Omarchy's settings go through its commands too (`src/settings.rs`): `omarchy-toggle-bar on` hides the bar and `off` shows it, `omarchy-toggle-nightlight` only toggles (its `--status` says which way it is), and `omarchy-theme-set` takes a name as `omarchy-theme-list` prints it. The screenshot and the night light's toggle start desktop programs, so they run through Hyprland's exec dispatcher (`hl.dsp.exec_cmd("…")`), outside the sandbox and without an exit status (ADR 0012); the Manifest's `commands` still lists them. The Manifest requires `OMARCHY_PATH` and `WAYLAND_DISPLAY`, since a Plugin starts only with `PATH`, `HOME`, `LANG` and the env it requires, and those commands need them. A test checks the Manifest's `commands` against the commands the tools run. Its tests serve a fake Hyprland socket under `/tmp` and put fake commands, written with shell builtins only, on its `PATH`. Its `[access] write` names only `omarchy-theme-set`'s lock files in `$XDG_RUNTIME_DIR`, never the dir itself, which holds lucyd's socket and other apps'. `tests/omarchy.rs` in lucyd installs the real binary as shipped, puts its fake commands in the Plugin folder (the only place the sandbox lets them run from) behind a `PATH` symlink, and checks they can write those locks and nothing else there; `cargo test -p lucyd` on its own needs `cargo build -p lucy-omarchy` first.
- **Screen tools (ADR 0008):** a Manifest tool marked `screen = "look" | "click" | "key" | "probe"` is left out of the tool list and refused when `[screen] enabled = false` (`SessionTools::offers`). A `look` asks "I need to look at your screen. Okay?" once per Session (`SessionTools::look`); a non-yes holds for the Session. Each allowed look bumps `SessionTools::looks`, and the runner shows the `looking` mark until that Turn ends; its `select!` arm comes before the model's events, so a look is seen before the end of the Turn that made it. Image content in a Plugin result passes to the model untouched; the fixture Plugin's `look` returns one. The Omarchy Plugin captures through its `Screen` trait (`Grim` for real, `FakeScreen` in its tests; `Plugin::with_grim` runs a fake `grim` for the commands check) and scales to at most 1568 px on the long edge and 1.15 MP, the smallest limit of the Claude models, so the API never resizes it and coordinates in the image stay true. At start lucyd calls `Thinking::sweep`, which deletes the conversations (named by UUID) left in its own work dir's `projects/` folder by a crash.
- **`requires`:** lucyd checks a Manifest's `requires` against `Options.plugin_env` (`plugins::Environment`), which Plugins also start with. `Harness::with_env` sets exactly that environment, so a test that needs `PATH` names it.
- **Fixtures test harness:** `crates/lucy-news/tests/support/mod.rs` runs a Plugin's MCP server in-process through a real MCP client and answers its web requests from `tests/fixtures/web/<host>/<path>`: `https://feeds.npr.org/1001/rss.xml` is `feeds.npr.org/1001/rss.xml` there, and a home page, `https://dailyplanet.example/`, is `dailyplanet.example/index.html`. A URL with no recording fails, as an unreachable site would. The Plugin template copies it (`crates/lucyd/plugin-template/tests/support/mod.rs`, whose rustdoc stays for the Delegate); a new Plugin swaps `News` for its own server and keeps its one way out to the web behind a trait like `Web`. Plugin tests never touch the network.
- **Confirming:** Confirmations, Approvals and Plugin mid-call questions all go through `runner::ask`, which queues a `Command::Ask` for the open Session. Tests shorten the 8 s wait with `[confirmation] timeout_secs`. `Harness::request_approval` starts a spoken Approval (`Daemon::request_approval`; nothing on IPC reaches it, and the model's `approve_plugin` only starts it, through `Host::ask_approval`), and `FakeThinking::watch_tools` holds a relay open to see `tools/list_changed`. The fixture Plugin's `ask` tool asks a question through `input_required`; `ask_url`, `ask_two` and `ask_secret` ask the forms that open the Input dialog.
- **Mid-call questions:** `plugins::questions` reads a form elicitation into Input dialog fields, or a spoken question when it is one plain string field. `rmcp` puts an elicitation's `_meta` in the request's `extensions`, not its params, so `lucy/secret` (ADR 0011) is read from there. A secret is kept through `Host::keep` before the Plugin gets `provided`.
- **Fake executables:** write them from a child process (see `fake_notify_send` in `notify_send.rs`). A fd this process holds open for writing can leak into a child another test forks, and running the file then fails with "Text file busy". lucyd follows the same rule: it writes a Plugin's executables from a child (`cp` in `plugins::authored`, `sh -c 'cat >'` in `plugins::manage`).
- **MCP relay:** a model process reaches lucyd's private MCP socket through `lucy mcp-relay`, which opens each connection with a line holding its per-spawn token. lucyd answers `ok` and then speaks MCP, or `refused` and hangs up. `mcp::Relays::issue` makes the token; dropping the returned `Token` revokes it. The relay reads the `ok` line a byte at a time, so nothing after it is consumed, and copies the socket to stdout by hand, flushing each read: `io::copy` from the socket to a stdout pipe stalled, holding replies back. A Session model sees the Built-in, Plugin and desktop tools; a Delegate sees only the Delegate tools.
- **Plugin protocol:** lucyd speaks the 2026-07-28 MCP protocol to Plugins first, which `input_required` needs and which has no `initialize`; older Plugins get the `initialize` handshake through `ClientLifecycleMode::Auto`. Dropping a call future cancels the call on the Plugin, which is how a Barge-in stops an unconfirmed call.
- **Sandbox:** a Manifest's `[access] network` hosts are declared and shown, not enforced in v0.1. Landlock lets a Plugin read and run the system paths, its own folder and its `read` paths, and write only its `write` paths and its private state dir. A declared path may start with `~/` or `$NAME`, taken from the Plugin environment (`plugins::Environment`); it is left out when the variable (or `HOME`) is unset, empty, relative or holds a `..`. A declared path containing a `..` component makes the Manifest invalid, so the Plugin is broken. A rule is added only for a path that exists when the Plugin starts. Connecting to a Unix socket needs no rule: lucyd's Landlock ABI (V5) doesn't confine it. A Delegate, and the `build.sh` and `test.sh` it submits, get only their workspace plus `/proc`, with the network open; `/dev/null` and `/dev/urandom` are always allowed.
- **Desktop:** the real Launcher starts apps through `uwsm app --` when uwsm runs, so each app gets its own systemd scope instead of living in lucyd's. A thread reaps each child.
- **Authoring:** `Thinking::open_delegate` spawns a Delegate under Landlock (`plugins::sandbox::confine_delegate`). It runs `plugins::sandbox::delegate_program`: a Provider's `program` as given, else the CLI found on `PATH` past symlinks and a mise shim (`mise which <name>`, asked unconfined), and only that executable's folder is made readable, never mise's config or installs; `Thinking::executable` reports it for `provider.check`. A Delegate's stderr is piped and its last lines kept: a dead Delegate sends `ThinkingEvent::Died(Exit)` with its exit status and stderr tail, and an error `result` line (`is_error` or an `error_*` subtype) sends `Failed(message)` (a Session treats it as `TurnEnd`). A build that gives up logs why; the stderr tail goes only to the journal and a one-line form to the notification. `FakeDelegate::open_on` runs later Delegates on a real adapter (a fake `claude`) while the Session stays scripted. A Codex Delegate's thread runs with `danger-full-access`: lucyd's Landlock rules confine it, not Codex's sandbox, so it keeps the network to fetch dependencies. In the harness, `thinking.delegate` is the scripted Delegate: read its Turns, write the Plugin into `workspace().dir` with `stage_plugin`, and call the Delegate tools through its relay. On `submit_plugin` lucyd runs the staging dir's `build.sh` then `test.sh`, sandboxed, so a test scripts a pass or a failure there. Lucy's build lines and questions wait in the runner until the Session is quiet (`Command::TurnOrNextSession`, `runner::When`); `barrier` in `tests/authoring.rs` orders a test after them. A build outlives its Session: its question and Approval go through `runner::ask_when_quiet_or_next_session`, which keeps them in the runner for the next Session; "Is that the one?" is `When::Kept`, kept behind the answer's Turn without a notification of its own. A budget counts on `Adapters.clock` (see **Clock** above). With no Session open, or if it ends first, a build line is shown as its Build notification, then told once at the next Session start; its text is for the model, never shown. "cancel it" is matched locally in `session::Session`, never sent to the model. The template (`crates/lucyd/plugin-template/`) is built into lucyd; build it by hand after changing it.
- **Hand-off:** `hand_to_claude` starts a `hand_off::Job` through `Thinking::open_hand_off` with an `adapters::HandOff` (folder and whole environment). lucyd captures the environment with `$SHELL -lic 'env -0'`, both taken from `Options.plugin_env`, which is lucyd's own environment and the fallback; the 5 s wait counts on `Adapters.clock`. The `claude` adapter removes the billing variables from it (the guard), runs with `--setting-sources user,project,local`, the relay added beside the user's MCP servers and `--permission-prompt-tool mcp__lucy__permission`, and keeps the transcript. Its `result` line arrives as `ThinkingEvent::Final`, and the conversation id as `ThinkingEvent::Conversation`. A Hand-off stops when its Session ends. In the harness, `thinking.hand_off` is the scripted Hand-off (`hand_off()`, `answer`); its `open_on` runs it on a real adapter, with `Harness::with_env` as lucyd's environment (the fake `claude` records `./argv` and `./environ` in the folder).
- **Credentials:** `lucy_config::credentials::CredentialStore` is the seam to the Secret Service (`SecretService`, through `oo7`), shared by lucyd (`Adapters.credentials`, read when a Plugin starts for a call; a missing one is asked for in a `secret` Input dialog after any Confirmation, `Host::ask_missing`) and `lucy credentials <plugin>` (writes). Tests use `Harness::credentials` or their own fake; never `SecretService`, which is the user's real keyring. `assert_nothing_private_on_bus` counts entered values as private.
- **Input dialog:** `input::Dialogs` (lucyd) holds the `input` role and the one open dialog. A question reaches it through `runner::ask` with `Expects::Typed(Dialog)`: once Lucy has said its line, the runner opens it on the holder, or runs `lucy input --socket <path>` through `Launcher::open_terminal`; when nothing claims the role within `runner::CLAIM_WAIT` of the launch (on `Adapters.clock`), it counts as no terminal, and the Session sits in Typing until the holder answers, a cancel phrase, the `[input]` timeout or the Session's end; dropping the runner's `OpenDialog` sends `input.close`. `input::fill` asks any fields, `input::ask` is `ask_typed`'s one-field question and `input::ask_for` is one named field with its own spoken words (a missing credential's, "your Linear API key"), and `Daemon::ask_typed` asks it from a test (the `lucy` crate's `Home::ask_typed`). In the harness, `Harness::input` claims the role and `Harness::answer_input` (or `answer_fields`) types an answer, which `assert_nothing_private_on_bus` counts as private; `launcher.terminals()` and `launcher.no_terminal()` cover the fallback.
- **Private data:** after a Session ends, `assert_nothing_private_on_bus()` checks that nothing private reached the public socket. lucyd's log can't be captured in-process (libtest captures `eprintln!`), so `plugin_questions.rs` and `credentials.rs` rerun a secret test as a child with `--nocapture` and `RUST_LOG=trace`, and checks the child's stderr, which holds lucyd's log and the Plugin's stderr. `lucyd::start_log` is lucyd's own logger: it holds `rmcp` to warnings, since rmcp's trace prints whole MCP messages (tool results and screenshots), so a test of what reaches the log starts that one, as `screen.rs` does.
- **Model text:** when a Harness is dropped, it fails the test if any notification showed text written for the model; the markers are `lucyd::model_text::MARKERS`, so new model text starts with one of them.

## Adapters (STT, Thinking, TTS)

- **Lifetime:** an adapter keeps the event sender it was given alive for as long as its handle. Today, a dropped sender makes the runner spin on the closed channel.
- **Sentences:** the Thinking adapter finds sentence boundaries itself and emits `SentenceEnd`. The Session sends each sentence to TTS.
- **Placeholders:** `Adapters::inert()` stands in for Providers that haven't been built yet.
- **Speaker:** `Speaker::sound` queues a cue that sends no event; if a cue is the last thing queued, it plays out even when the Speaker is dropped straight after. So the Voice preview queues the Closing sound only once its sentence has played, and a Session that interrupts it cuts it off at once. `duck(true)` turns playback down while the user may be cutting in; the echo canceller's reference is what actually plays. `stop` drops everything queued at once, sends no event for it and unducks.
- **Notifications:** each `Status` notification (Session start, Confirming, end) replaces the last one that offered an action, so a stale End button doesn't linger. `Reply`, `Problem`, `Details` and `Build` replace nothing: the End button stays, and a Session end after a problem doesn't hide it.
- **Model restarts:** when the model process dies, the runner opens it again once per Turn and resends the pending Turn. Queued questions are dropped unanswered, since the resent Turn asks again if it needs to. A second death ends the Session with a notification.
- **Runner ordering:** the runner's `select!`s are `biased`, and their arm order is behaviour. Outside a Session the Wake word wins over speech, so the utterance it starts belongs to the Session it opens. In a Session, what the model and speaker report comes first, so a Turn that ended or a sentence that finished playing is seen before a request or reply that came after. `speech` comes before `speaking`, since an utterance is cut before the user stops speaking. lucyd tells the gate Lucy is speaking before it publishes Speaking, so the gate is open by the time a client sees her speak.
- **First run:** it lasts until the introduction's Turn ends (`Persona::introduced`), so an unusable Provider doesn't use it up.

## Public IPC

New methods, events and enum variants go in `crates/lucy-ipc/src/schema.rs`. Regenerate the committed schema with `LUCY_UPDATE_SCHEMA=1 cargo test -p lucy-ipc`; a test fails if it drifts.

## Real `claude`

Automated tests use the fake `claude` and the recorded fixtures in `crates/lucyd/tests/fixtures/claude/`. The fake reads its `--version`, `auth status` and turn overrides from its working directory; its header says how. `Harness::with_thinking` runs lucyd with the real adapter against it (`tests/subscription_guard.rs`). lucyd runs `claude` and `codex` in a Lucy-owned work dir, so no project's `.mcp.json`, hooks or `AGENTS.md` apply. Unless a Provider sets `allow_api_key`, lucyd removes `BILLING_ENV` from claude's environment: everything above `CLAUDE_CODE_OAUTH_TOKEN` in Claude Code's credential precedence. `apiKeyHelper` lives only in settings files, which `--setting-sources ""` keeps out. The subscription guard (`claude/guard.rs`) checks health with no model call: the binary runs and `auth status` shows a claude.ai login. Its verification is one real "Reply OK" Turn, which must show `apiKeySource: "none"` and a `rate_limit_event`; it runs before a Session whenever `claude --version` differs from the last version that passed (`.verified-claude-version` in the work dir), and on every explicit check. A Turn is interrupted with stream-json's control interrupt; if claude doesn't acknowledge it within `INTERRUPT_ACK_WAIT`, lucyd sends SIGINT, which ends the process, and a new one resumes the conversation (`--resume`). Conversations are kept on disk for that, under the config dir's `projects/<cwd with non-alphanumerics as ->`, and deleted when the Session ends. The live check is `cargo test -p lucyd --test claude -- --ignored`, and it spends the user's subscription, so run it only when a ticket needs a real round trip.

## Real `codex`

`fixtures/codex/fake-codex` stands in for `codex app-server`. Its turns are written from the protocol's generated types (`codex app-server generate-ts`), not recorded. Its header says what it reads from its working directory. `tests/codex_session.rs` runs Sessions through it. `codex app-server --print-startup-config` checks `-c` settings without a model call. The live check is `cargo test -p lucyd --test codex -- --ignored`. It spends the user's ChatGPT subscription.

## Real Piper

lucyd runs `python -m piper.http_server`, which needs the `http` extra: install with `uv tool install 'piper-tts[http]'`. Clear `PYTHONPATH` when running Piper by hand (`env -u PYTHONPATH ...`): a `PYTHONPATH` pointing at the system site-packages loads the wrong numpy and Piper fails to import. Voices live in `$XDG_DATA_HOME/lucy/voices/` (`en_GB-cori-medium.onnx`, its `.onnx.json` and `MODEL_CARD`); `piper -m <voice>.onnx -f out.wav` synthesises a line to check. With lucyd running, the hidden `lucy say "<text>"` (a Voice preview) speaks a line through lucyd's own voice and speaker, with no model call. The default voice, `en_GB-cori-medium`, was chosen because its whole training chain is CC BY 4.0; its `MODEL_CARD` is fetched too because its licence asks for it to be kept. A `piper` binary on `PATH` proves nothing (Arch's `extra/piper` is a mouse tool), so lucyd uses the interpreter behind a `piper` script, then `python3`, and checks it can import `piper`. The server binds to 127.0.0.1, since Piper defaults to 0.0.0.0. Live checks: `LUCY_PIPER_PYTHON=… cargo test -p lucyd --lib piper -- --ignored` downloads the voice (it needs the network), and `live_piper_speaks_through_the_speakers_with_levels` plays on the default speaker: listen for it.

## Hearing (mic, VAD, Whisper)

- **Harness:** `Harness::hearing(config)` runs the real DSP thread and endpointing between `FakeMic` and `FakeVad`; the fake VAD reads each sample's value as the speech probability, so tests feed levels (`SPEECH`, `SILENCE`).
- **Barge-in:** under `Harness::hearing`, `Harness::echo` is Lucy's echo canceller (set its ERLE, and `set_echo_heard` for whether Lucy's voice reaches the mic); `FakeMic::use_pulseaudio` turns Barge-in by speech off. The gate counts time in samples, so call `mic.wait_until_heard()` before a state change whose timing matters, and end a speech feed with a little silence so its last 10 ms frame and VAD chunk are complete. Lucy's echo canceller is `sonora` (pure-Rust AEC3), not the C++ `webrtc-audio-processing` the spec names.
- **Idle is the usual state:** the DSP thread runs every frame, in and out of Sessions, and lucyd mostly sits idle in a quiet room. Check anything adaptive in it (the canceller, its pre-gain, the meter) against minutes of room noise.
- **AEC bench:** `tools/aec-bench/` (README there) replays real recordings through lucyd's `Sonora`, Silero and a copy of the gate; tickets 27 and 28 judged their acceptance on it. It isn't in the workspace or `scripts/check.sh`, so build it with `cargo build --release` in its folder after changing lucyd's audio API. Its recordings (`runs/`) are gitignored and stay on the machine that made them.
- **Gate log:** `RUST_LOG=lucyd=debug` logs the gate's inputs for each VAD chunk while its window is open or Lucy's voice is in the canceller's reference (`EchoCanceller::lucy_playing`), so a run where the window never opens still shows them (speech probability, ERLE, `echo_heard`, settled, the window, mic level before and after the canceller, Wake word score, the event), the speaking flag as the DSP thread gets it, the canceller's pre-gain and reference frames every 0.5 s while Lucy speaks, and the gate events and Wake words the Session receives. lucyd logs nothing through `log` without it.
- **Mid-utterance:** the DSP thread reports whether the user is speaking (`Adapters::speaking`); the Session's timers hold while they are. Without `Harness::hearing`, `Harness::start_speaking` starts an utterance and the next `say` ends it.
- **Models:** lucyd loads `ggml-<model>.bin` from `$XDG_DATA_HOME/lucy/models`. Silero is bundled in `crates/lucyd/models/`. The bundled Silero is silero-vad v6.2.3's If-less opset-18 export (MIT) with `sr` made a constant 16000; with graph optimisation on, tract folds away the remaining 16/8 kHz `If`. Without both, a chunk costs 40 times as much. Whisper on the CPU gets a 384-frame (7.68 s) encoder context, which makes short commands much faster; longer utterances get the full 30 s, because a context cut to fit makes Whisper repeat itself.
- **Capture and playback:** capture asks cpal for mono 16 kHz, so the sound server resamples; cpal tries PipeWire, then PulseAudio, then ALSA. A cpal stream can't move threads, so a capture thread owns it until the handle drops or the device goes. On PipeWire every cpal stream of the process shares one `node.group`, so playback and capture share a driver. The playback callback only moves samples between lock-free rings; a player thread feeds it, reports each sentence once it has played, sends the level about 30 times a second, and downsamples what played (rubato FFT, the only resampler Lucy runs) to the 16 kHz echo reference. The echo canceller's design is ADR 0009.
- **DSP order:** the Wake word is checked before endpointing, so the Session it opens gets the utterance it started. Its score is metered before the detection is sent, so a test that hears it sees the score.
- **Superwhisper:** lucyd uses the raw ASR text, not the cleanup model's rewrite, so a command isn't paraphrased. Superwhisper reports a rejected file only through `read` and `status`, hence the 10 s timeout.
- **Wake word:** `Harness::wake()` scripts a detection. Under `Harness::hearing`, the fake wake word hears it where a run of `WAKE` frames starts, and the fake VAD hears those as speech. The real engine's model is `[wake_word] model`; unset, lucyd installs the bundled `hey_lucy.onnx` into `$XDG_DATA_HOME/lucy/models/wake/`. The model's file name is the phrase stripped from transcripts and named in the bar panel (`lucy_config::WakeWord::word`). The bundled `hey_lucy.onnx` was trained with LiveKit's recipe; `crates/lucyd/models/wake/README.md` says how to reproduce it.
- **Live checks:** `cargo test -p lucyd --test whisper --test silero --test mic -- --ignored`. Outside the main checkout set `LUCY_WHISPER_MODELS` (a dir of ggml models) and `LUCY_SPEECH_WAV` (a speech recording); they default to the voice-loop prototype's.
- **PipeWire in a smoke run:** a short `XDG_RUNTIME_DIR` hides PipeWire, so cpal falls back to ALSA. Also set `PIPEWIRE_RUNTIME_DIR=/run/user/$UID`.

## Setup and the `lucy` pages

- **Shape:** `lucy` (no arguments), `lucy setup` and `lucy credentials <plugin>` are one full screen (ratatui on crossterm), `menu::run`, opened at `menu::Open`; they refuse a stdin or stdout that isn't a terminal. It is a list of sections (`sections::Section`), each a page: `ui::Rows` lists its rows and the letters that act on them, and a row's questions run one at a time on `ui::Ui`. A section that needs lucyd still opens while it is stopped, says so and offers to start it. Approvals are granted only by voice, so their section only revokes. Esc anywhere is `Stop::Back`: on a row's question it goes back to the page, on a page to the list. The walk (no `config.toml`, or `lucy setup`) opens each section with a last "Next" row; after a row is picked the cursor moves to the next one, so Enter alone walks every suggestion. Sections read their paths and `PATH` from `lucy::Env`, never the process environment. Ctrl-C arrives as a key in raw mode; ratatui's panic hook restores the terminal. An installer runs outside the full screen (`Keys::outside`), since it may ask for a password.
- **Settings:** `lucy::settings` is the one writer of `config.toml` (`settings::write` of `Change::Set`/`Unset`, through `lucy_config::set`/`unset`, comments kept): `settings::Key` is each setting `lucy` changes, and `Key::applies` says whether lucyd takes it up at the next Session or only after a restart (Whisper's model, which stays loaded). Installing Piper also needs a restart: lucyd looks for it once, at start. A new setting gets a `Key` and its `Applies`, read from where lucyd loads it. `lucy set`/`unset` also take `stt` (`settings::SPEECH`), the panel's Speech-to-text row: `superwhisper` or one of Whisper's models, written as `stt.kind` and `whisper.model` together.
- **Tests:** `crates/lucy/tests/support/mod.rs` gives each test its own XDG dirs, an in-process lucyd with inert adapters, and a `PATH` holding only the fakes a test writes (`Home::fake`, logged to `<name>.log`). `Home::with_mic(level)` gives its lucyd a microphone that stays at that RMS level, for the meter. `Home::tui` runs `lucy` in-process on ratatui's `TestBackend`, pressed by a `ui::Script`, with a `FakeStore` keyring (`Home::tui_with` takes an `Env` and store); a script that runs out, or has keys left over, fails the test. `Script::then` runs something while a question waits, and `idle` presses nothing more, for a question `Ui::close_on` watches (`lucy input` watches for `input.close`). `Tui::shown` is every piece of text shown, rows and options included; `Tui::screen` is the last screen. `Home::spawn_lucyd` starts lucyd mid-test, as a fake `systemctl start` would. Plain commands still run the real binary.
- **Tests inside lucyd:** `test.mic_level` and `test.wake_word` run in the Session runner (`runner/setup.rs`), refused while a Session is open. Under `Harness::hearing`, the fake wake word's score is each frame's first sample.
- **systemd:** the units are `dist/systemd/*.service`. When systemd doesn't know `lucyd.service`, the Service section and starting lucyd write them to `$XDG_CONFIG_HOME/systemd/user/` running the binaries beside `lucy`. `systemd::run` (the Service section's letters, and `lucy service start|stop|restart`) clears a crashed lucyd's start limit before a start or restart. The Service section's row asks whether Lucy starts at login, so a yes enables again even when lucyd already is. Tests use a fake `systemctl`; never enable the units in your own session.

## Bar panel

- **Shape:** `omarchy-plugin/` is an Omarchy (Quickshell) bar-widget plugin. Its QML holds no product knowledge: it reads `lucy status --follow --json` (`lucy::panel`), writes through `lucy set`/`lucy unset` (a choice's `key`), and runs `lucy service` and `lucy end`, never `systemctl`.
- **Input dialog:** the panel holds the `input` role through `lucy input --json` (`lucy::input::hold`), which keeps running, reclaims the role whenever lucyd comes back, prints lucyd's `input.open`/`input.close` lines as they came and sends each `{"method": "input.answer"|"input.cancel", "params": ..}` line written to its stdin. It passes field kinds through unread, so a new kind needs only a box in `Panel.qml`'s `InputBox`. A question opens the panel on the dialog, with the keys in its first typed box (the dialog is the `KeyboardPanel`'s `focusTarget` while it's up, since the panel gives that the keys as it opens); Send empties every box before the answer goes, and a secret is never put on a command line. Option labels come from `i18n/en.json` where it has an `option.<value>` string (Superwhisper), else the value itself. A new choice goes in `panel::Snapshot` with its key, plus a row in `Panel.qml` that binds it by its snapshot name; `Service.qml` reads every choice the snapshot holds.
- **Lifetime:** `lucy status --follow` asks Linux for SIGTERM when its parent dies (`PR_SET_PDEATHSIG`), since the bar gives it no stdin; `lucy input --json` ends when its stdin closes, which happens when the bar dies.
- **States:** lucyd's socket says waiting or session; while it's away, `systemd::activity` (`systemctl show`) says stopped, starting or failed. lucyd is `Type=exec`, so systemd calls it active before it listens: active without a socket is starting for `panel::STARTUP` (a minute), then failed.
- **Install:** each yes to starting at login in the Service section links the plugin to `$XDG_CONFIG_HOME/omarchy/plugins/lucy-panel` (`Env.omarchy`) when that dir exists, replacing an older link (`panel::link`). It is found through `Env.bin`: `omarchy-plugin/` beside `lucy`, else in the checkout whose `target/<profile>/` holds `lucy` (with the shared `target/`, the main checkout). If neither has it, the section says so and the enable stands. The user adds it to the bar. Lucy never edits `shell.json`.
- **Checks:** `omarchy-plugin/tests/run.sh` runs `Panel.qml` offscreen in Quickshell against a fake `lucy`, `systemctl` and `omarchy-launch-tui`, then checks the commands it ran, that none was `systemctl`, and the replies the Input dialog wrote to the fake `lucy input --json`. The harness feeds `input.open` and `input.close` straight to `Service.inputEvent`, and presses keys with QtTest's `TestEvent`, which is why the panel sits in a window there; `omarchy plugin validate omarchy-plugin` checks the manifest. Neither is in `scripts/check.sh`, since CI has no Quickshell: run both after changing the plugin.

## Unix sockets

Socket paths are limited to about 108 bytes. The session scratchpad path is too long for a smoke run, so put the socket under `/tmp` or a short tempdir.

## Implementer subagents

The `tdd` skill asks the user to approve seams first, and a subagent can't ask. The ticket's acceptance checks driven through the harness, plus the adapter traits above, are the approved seams. A ticket that needs a new adapter trait names it in the implementer's report. The ticket's `Seams:` line says which shared seams it owns and which it only uses.

The last step before reporting: stop every background Bash task you started (TaskStop each one) and confirm none remain. A running one keeps your worktree locked.

Worktrees share the main checkout's `target/` and build with 8 jobs, through `CARGO_TARGET_DIR` and `CARGO_BUILD_JOBS` in the machine's `.claude/settings.local.json`. Keep them as set. "Blocking waiting for file lock on build directory" means another worktree is building; wait for it. On a new machine, create that file with its own checkout's path:

```json
{ "env": { "CARGO_TARGET_DIR": "/path/to/lucy/target", "CARGO_BUILD_JOBS": "8" } }
```

Without it, each worktree builds everything cold in its own `target/`, and parallel agents can stall the desktop.

## Merging

A merge that combines two tickets' changes to the same seam (both edit one adapter trait, the Session start, the notification fallback) gets one harness test of the combination before the merge commit. Each ticket's own tests pass alone; the combination is where the bugs were in slice 2 (a refused Provider swallowing the first-run introduction; a TTS-failure notification replacing the End button).

## Agent Brief

**Category:** enhancement
**Summary:** Add the public IPC request `test.voice_preview {text}` and a hidden `lucy say "<text>"` CLI command that calls it.

**Current behavior:**
lucyd only speaks inside a Session. The spec's public IPC request list already names `test.voice_preview`, but it isn't in `lucy-ipc` or the committed schema. The only way to hear the real voice is to open a Session (which spends the user's subscription) or to run Piper by hand.

**Desired behavior:**
- `test.voice_preview {text}`: lucyd opens a Speaker through the TTS adapter (`Tts::open`) on the configured `[audio] speaker`. No Session is involved. It plays `Sound::Start`, then `text` in the voice lucyd is running, then `Sound::Closing`. It replies with an empty result object once playback has finished.
- While a Voice preview plays, lucyd still reports `Idle`. It sends no `state` change, no `level` events and no `session_id`, and shows no Indicator. Nothing reaches the model.
- Errors are JSON-RPC errors with a clear message and never raise a notification:
  - **Session open:** refused.
  - **Another Voice preview playing:** refused as busy. There is no queue.
  - **Empty text:** refused.
  - **TTS unavailable, or the sentence fails to synthesise or play:** the reason, e.g. "Piper isn't installed".
  - **A Session opens partway through (wake word or `session.start`):** the Session wins. The preview stops at once, its request returns an "interrupted" error, and the Session starts and runs normally with its own Start sound.
- `lucy say "<text>"` is a hidden subcommand (`#[command(hide = true)]`, like `mcp-relay`). It connects as an ordinary client, sends the request and waits for the reply. It exits 0 on success, and prints the error to stderr and exits non-zero otherwise.

**Key interfaces:**
- `lucy-ipc`: params type `VoicePreview { text: String }`, result an empty object. Register `test.voice_preview` in the schema's `x-methods`, then regenerate the committed schema (`LUCY_UPDATE_SCHEMA=1 cargo test -p lucy-ipc`).
- `Tts::open` and `Speaker::speak` / `Speaker::sound`: used as they are. `SpeakerEvent::Played`, `Failed` and `DeviceLost` tell lucyd when the preview has finished or failed. No trait change should be needed. If one is, say so in your report.

**Acceptance criteria:**
- [ ] Harness test: `test.voice_preview {text: "hello"}` makes the fake TTS receive Start, "hello" and Closing in that order. The reply arrives after playback, and lucyd's state stays `Idle` throughout with no `level` events.
- [ ] Harness test: refused while a Session is open, refused as busy while another preview plays, and refused for empty text.
- [ ] Harness test: the fake TTS fails the sentence, and the request returns an error naming the reason. No notification is sent.
- [ ] Harness test: a Session started mid-preview stops it, the preview request returns "interrupted", and the Session completes a Turn normally.
- [ ] `assert_nothing_private_on_bus()` passes after a preview: the text never appears in anything lucyd sends to a client.
- [ ] `lucy say` is missing from `lucy --help`. It exits 0 on success and non-zero with the error on stderr on refusal (driven through the real `lucy` binary in a harness test).
- [ ] The committed schema includes `test.voice_preview`. `scripts/check.sh` passes.

**Out of scope:**
- A `voice` field to preview a voice other than the running one. Ticket 20 adds it as an optional field when its voice picker needs it.
- A flag to turn the Start and Closing sounds off.
- `test.mic_level` and `test.wake_word` (ticket 20).
- Any TUI work.

# Lucy's audio stack beside the desktop

Ticket: [25-audio-stack-coexistence](../issues/25-audio-stack-coexistence.md). Measured 2026-11-15 on the dev machine (RX 7800 XT, RADV Vulkan, PipeWire 1.6.9, WirePlumber), against the deployed lucyd rather than the voice-loop prototype, which lucyd has superseded. Builds on [audio-io.md](audio-io.md) and [local-stt-tts.md](local-stt-tts.md). Probes and raw output: `prototypes/audio-coexistence/` (`results.txt`).

## In short

- **Whisper and Superwhisper share the GPU fine.** With Superwhisper's three Vulkan workers resident and idle, lucyd's `small.en` takes the same time as with them unloaded (p50 103 vs 102 ms for a 5.6 s utterance). With both transcribing at once, Whisper slows to p50 110 / p95 135 ms and Superwhisper from ~196 to ~232 ms. Nothing failed, and every transcript was correct. The workers hold ~3 GiB of the 16 GiB of VRAM. Nothing to change. Only a user who runs both at the same moment sees the overlap, and it is small next to the 2.5 s budget.
- **One driver: confirmed.** cpal puts both lucyd streams in `node.group = cpal-<pid>`. `pw-top` shows lucyd's capture (16 kHz mono) and playback (22 050 Hz stereo, opened only while Lucy speaks) both following the pinned ATH-M50x mic's driver, with the Pebble V3 sink as a follower in the same graph, though they are two separate USB devices. PipeWire rate-matches the follower sink, so the AEC reference and the mic stay in step. The premise in 13 holds.
- **A device that disappears is not reported the way lucyd expects. That's a bug.** On the PipeWire host, cpal 0.18.2 reports a pinned node's removal as `ErrorKind::StreamInvalidated` ("target not found"), not `DeviceNotAvailable`. lucyd's `audio::cpal::is_device_lost` only matches `DeviceNotAvailable | HostUnavailable`, so:
  - **Mic lost outside a Session:** lucyd logs `microphone error: target not found` and goes deaf. There's no notification and no reopen loop. It stays deaf after the device comes back, until lucyd restarts.
  - **Mic lost in a Session:** same log line. The Session ends on its own timer (listening → idle), not through the lost-device path (no `error` state, no notification), and lucyd is deaf afterwards.
  - **Pinned speaker lost:** `playback error: target not found`. The callback stops pulling, so `consumed` never reaches `written` and `Played` never arrives. A Voice preview never finished. In a Session this should leave Lucy in Speaking. That's inferred from the code, since the silence timer doesn't run in Speaking; it wasn't run mid-Session.
  - `tests/devices.rs` passes because the harness's fakes (`mic.lose()`, `lose_device()`) signal loss above cpal. No test covers which cpal error kinds count as lost.
  - Filed as build ticket [39](../../lucy-v0-1-build/issues/39-device-loss-stream-invalidated.md).
- **The default speaker is followed, not lost.** A stream on `"default"` gets `DeviceChanged` when the default node goes away and another takes over. The stream follows and keeps playing. lucyd ignores `DeviceChanged`, which is the right behaviour. cpal emits `DeviceNotAvailable` for a default stream only when no default is left. The user's config pins only the mic, so the speaker-hang case only bites users who pin a speaker.

## Method

- **GPU:** a temporary integration test (`gpu_bench.rs`) loaded lucyd's own `Whisper` adapter (`small.en`, Vulkan, release build) and timed 40–60 transcriptions of `voice-loop/hello.wav` after two warm-ups. It ran in three conditions: Superwhisper's workers unloaded (`superwhisper models unload`, reloaded afterwards), resident and idle, and resident while a loop fed Superwhisper `transcribe FILE` on the same recording at 16 kHz. Superwhisper's own `asr_ms` and `release_to_text_ms` came from `superwhisper read` after each run. Lucy's configured STT is Superwhisper, so these runs added ~30 entries to its history.
- **Graph:** `pw-top -b` and `pw-dump`, sampled while `lucy say` spoke a long line.
- **Device loss, cpal alone:** `device_probe.rs` opens one stream exactly as lucyd does (by node name, or the default), on a remap of a real device (`pactl load-module module-remap-source|sink`), then unloads the module mid-stream. A bare `module-null-sink` source is a poor stand-in: it has no driver, the stream never links to it, and WirePlumber relinks the stream to the default source once its target goes.
- **Device loss, real lucyd:** the ATH-M50x card's profile set to `off` and back (`pactl set-card-profile`), outside a Session and during one opened with `lucy listen`, watching `lucy events`, the journal and `pw-link`. For the speaker, the config briefly pinned `speaker` to a remap of the Pebble, which was then unloaded during `lucy say`. The config was restored afterwards and lucyd restarted after each mic run to bring hearing back.
- **Not tested:** a physical USB unplug. Switching the card profile off removes the device's nodes the same way udev removal does as far as streams are concerned (WirePlumber destroys the target node, and the stream gets "target not found"). A pull of the cable during ticket 39's acceptance confirms it.

## What the Session error handling and `AudioIo` seam depend on

- A device loss arrives as `StreamInvalidated` for pinned nodes, and as `DeviceNotAvailable` only for a default stream with no default left. Treat both, plus `HostUnavailable`, as lost. A `StreamInvalidated` stream is dead whatever the cause, so ending the Session and reopening is the right response even for causes other than removal.
- There is no "device came back" event. Reopening has to poll. lucyd's existing 1 s reopen loop does that once it is triggered, and `find` falls back to the default when the pin is missing. After a lost pinned mic, Lucy therefore hears through the default mic (here the OBSBOT webcam) until the next reopen finds the pin again.
- `DeviceChanged` on a default stream needs no handling. The stream follows on its own. The AEC re-converges against the new path in its usual 3–6 s (23).
- The playback completion count (`consumed`) only advances while the device pulls. Anything that waits on it needs the lost-device path to stop the wait.
